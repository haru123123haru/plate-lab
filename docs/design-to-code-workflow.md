# デザイン → コード変換ワークフロー

## このドキュメントについて

Pencil（.pen）でデザインしたUIをコードに変換する際の作業手順。
「全画面をルーティングにしてしまい、後からモーダルに修正が必要になった」問題を防ぐためのガイド。

**使い方**: 新しいプロジェクトでデザインをコードに変換する前に、このファイルを読み込んでもらう。

---

## 背景（なぜこのガイドが必要か）

PLATE LAB の開発で起きた問題：

```
.pen ファイルに12画面のデザインがあった
  ↓
全画面を個別のルート（/page）として実装した
  ↓
実際には一部の画面は「モーダル」「シート」「ダイアログ」であるべきだった
  ↓
後から修正が必要になり、手戻りが発生した
```

**原因**: デザインファイルには「この画面はどう表示するか」の情報がない。
ルーティング（URL遷移）なのか、モーダル（重ねて表示）なのかは、デザインだけでは判断できない。

---

## ワークフロー（3ステップ）

### Step 1: デザイン読み込み & 画面一覧の作成

**Claude への指示例:**
```
.pen ファイルを読み込んで、全画面の一覧を作成してください。
各画面のスクリーンショットと簡単な説明をリストにしてください。
まだコードは書かないでください。
```

**出力例:**
```
画面一覧:
1. ログイン画面 — メール・パスワード入力、Google認証ボタン
2. ダッシュボード — プレート一覧、検索バー
3. メニュー — ナビゲーション項目一覧
4. プレート詳細 — ウェルマップ、プレート情報
5. 新規プレート作成 — フォーム入力
6. プロフィール編集 — ユーザー情報変更
7. 設定 — 言語・外観切替
...
```

---

### Step 2: 画面の表示方法を決定（最重要ステップ）

**Claude への指示例:**
```
各画面について、以下のどの表示方法にするか一緒に決めたいです。
選択肢を提示してください。
```

**表示方法の分類:**

| 表示方法 | いつ使うか | 実装 | URL変わる？ |
|---------|----------|------|-----------|
| **ページ（Route）** | 独立した画面。ブックマーク・共有したい | `app/xxx/page.tsx` | はい |
| **モーダル（Dialog）** | 確認・入力。背景が暗くなる | `<Dialog>` コンポーネント | いいえ |
| **シート（Sheet）** | 下/横からスライド。メニュー・フォーム | `<Sheet>` コンポーネント | いいえ |
| **タブ（Tabs）** | 同じページ内の切替 | `<Tabs>` コンポーネント | いいえ |
| **アコーディオン** | 詳細の展開/折りたたみ | `<Accordion>` コンポーネント | いいえ |

**判断基準チェックリスト:**

```
その画面に直接アクセスしたいか？（URLを共有したい？）
  → はい → ページ（Route）
  → いいえ ↓

元の画面に戻る操作が必要か？
  → はい ↓

一時的な操作か？（入力・確認・選択）
  → はい → モーダル or シート
  → いいえ → ページ（Route）

画面の情報量は多いか？
  → 多い（スクロールが必要）→ ページ or シート
  → 少ない（1画面に収まる）→ モーダル or ダイアログ

ナビゲーション的な性質があるか？
  → はい → シート（下からスライド）
  → いいえ → モーダル（中央表示）
```

**具体的に聞くべき質問:**

```
1. 「メニュー画面」はページ遷移？それともシートで開く？
2. 「新規作成フォーム」はモーダル？シート？別ページ？
3. 「ウェル詳細」はモーダルで表示？別ページに遷移？
4. 「設定の各項目（言語選択等）」はダイアログ？ページ内で切替？
```

---

### Step 3: 画面マッピング表の確定

Step 2 の結果を表にまとめて、実装前に確認する。

**PLATE LAB での最終的なマッピング:**

| デザイン上の画面 | 表示方法 | パス / コンポーネント | 理由 |
|---------------|---------|---------------------|------|
| ログイン | ページ | `/login` | 独立画面。URL直アクセスあり |
| 新規登録 | ページ | `/register` | 独立画面。URL直アクセスあり |
| ダッシュボード | ページ | `/` | メイン画面 |
| サンプル一覧 | ページ | `/samples` | タブバーで切替。独立した画面 |
| プレート詳細 | ページ | `/plates/[id]` | QRコードでURL直アクセスあり |
| マイページ | ページ | `/mypage` | タブバーで切替 |
| プロフィール編集 | ページ | `/mypage/edit` | 入力項目が多い |
| 設定 | ページ | `/settings` | タブバーで切替 |
| **メニュー** | **シート** | `<MenuSheet>` | 一時的なナビ。元画面に戻る |
| **新規プレート作成** | **シート** | `<NewPlateSheet>` | フォーム。元画面に戻る |
| **ウェル詳細** | **モーダル** | `<WellDetailModal>` | 情報表示。一時的に確認 |
| **言語選択** | **ダイアログ** | `<Dialog>` | 単一選択。即座に完了 |
| **外観選択** | **ダイアログ** | `<Dialog>` | 単一選択。即座に完了 |
| **プレート種別追加** | **ダイアログ** | `<NewPlateTypeDialog>` | 短いフォーム |

**Claude への指示例:**
```
上記の画面マッピング表に基づいてコードを実装してください。
「ページ」はルーティング（app/xxx/page.tsx）で、
「シート」「モーダル」「ダイアログ」は親ページ内のコンポーネントとして実装してください。
```

以下をコピーして Claude に渡す：

```

### 前提
- デザインファイル: [.pen ファイルのパス]
- docs/design-to-code-workflow.md を読んでワークフローに従ってください

### Step 1
.pen ファイルを読み込んで、全画面の一覧を作成してください。
各画面の名前と簡単な説明をリストにしてください。
まだコードは書かないでください。

### Step 2
各画面について、以下のどの表示方法にするか提案してください：
- ページ（Route） — URL が変わる独立画面
- シート（Sheet） — 下からスライドする一時的な画面
- モーダル（Dialog） — 中央に表示される確認・入力画面
- タブ（Tabs） — 同じページ内の切替

各画面の提案理由も添えてください。
私が確認・修正してから Step 3 に進みます。

### Step 3
確定した画面マッピングに基づいてコードを実装してください。
```

## よくある間違いパターン

### 1. 全部ページにしてしまう

```
× メニュー → /menu（ページ）
○ メニュー → <MenuSheet>（シート）

理由: メニューは一時的な操作。URL で直接アクセスする意味がない。
```

### 2. 全部モーダルにしてしまう

```
× プレート詳細 → <PlateDetailModal>（モーダル）
○ プレート詳細 → /plates/[id]（ページ）

理由: QRコードで直接アクセスするので URL が必要。
      情報量も多くスクロールが必要。
```

### 3. フォームの表示方法

```
入力項目が少ない（3個以下）→ ダイアログ or シート
入力項目が多い（4個以上）→ ページ or 大きめのシート
入力中に他の情報を参照したい → ページ（画面遷移）
```

### 4. 判断に迷ったら

```
「この画面のURLを誰かに送りたいか？」
  → 送りたい → ページ
  → 送らない → モーダル/シート
```

## 補足: Next.js App Router でのルートグループ

```
app/
├── (app)/          # 認証必須ページのグループ
│   ├── page.tsx    # / ダッシュボード
│   ├── samples/    # /samples
│   └── settings/   # /settings
├── (auth)/         # 未認証ページのグループ
│   ├── login/      # /login
│   └── register/   # /register
└── auth/
    └── callback/   # /auth/callback（OAuthコールバック）
```

`(app)` と `(auth)` は **ルートグループ**。URL には影響せず、
レイアウトやミドルウェアの適用範囲を分けるために使う。
