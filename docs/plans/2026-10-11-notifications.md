# 観察の時期と、放っておいたプレートを通知で知らせる（2026-10-11）

作成: 2026-10-11 / 更新: 2026-10-12（壁打ちの結果を反映） / Issue #18

## 目的

本人から「通知をつけたい」「PWA のようなモバイルの機能をつけたい」という声が出た。知らせたいのは次の2つ。

- **観察のリマインド**: 仕込んでから、プレートごとに決めた日数が経ったら、観察するよう知らせる
- **放っておいたプレート**: しばらく観察していないプレートを知らせる

アプリを開いていなくても届くよう、Web Push で送る。あわせて、ホーム画面のアイコンに観察どきのプレートの枚数（バッジ）を出す。

## 今あるもの

- `app/manifest.ts` で、ホーム画面に追加すると `standalone` で開ける。ヘルプ（`lib/help.ts`）とホームのカードに追加の手順がある
- Service Worker は無い
- `UserSettings` に `notifNewPlate`・`notifStatus`・`notifReminder` の列があり、`lib/actions/settings.ts` で書き換えられる。ただ、画面には出ておらず、何にも使われていない
- プレートのメモ（`Plate.notes`）は1つの文章で、いつ書いたかを持っていない

## 決めたこと

### 届け方は Web Push

- `public/sw.js` に Service Worker を置き、`push` を受けたら通知を出し、押したらそのプレート（まとめた通知ならホーム）を開く
- 鍵は VAPID。公開鍵は `NEXT_PUBLIC_VAPID_PUBLIC_KEY`、秘密鍵は `VAPID_PRIVATE_KEY`、連絡先は `VAPID_SUBJECT` として Vercel の環境変数に置く。送るのは `web-push` パッケージ
- iPhone では、ホーム画面に追加したアプリからしか通知を受けられない（iOS 16.4 以降）。設定画面で、ホーム画面から開いていないときは、その旨と手順（ヘルプ）を出す
- 通知の許可は、ボタンを押したときだけ求める。開いた途端には聞かない
- `/sw.js` はログインの振り分け（`proxy.ts`）から外す。ログインしていなくても取れるようにする

### 送る時間と回数

- 1日1回、日本時間の朝9時台に送る。Vercel Cron（`vercel.json` の `crons`、UTC の `0 0 * * *`）で `app/api/cron/notifications/route.ts` を呼ぶ。Hobby プランでは指定した時刻の1時間のうちのどこかで動く。`CRON_SECRET` で、Vercel 以外からは呼べないようにする
- 1人に1日1通にまとめる。知らせるプレートが1枚ならその名前を、複数なら「3枚のプレートが観察どきです」のように出す
- 知らせるものが無い日は送らない

### 何を知らせるか

ゴミ箱のプレートは除く。「もう見なくてよいプレート」を除く仕組みは、今回は作らない（放置の知らせは1回だけ、リマインドも1回だけなので、余計な通知は少ない）。

- **観察のリマインド**: 仕込み日（`setupDate`）から、プレートごとに決めた日数（`reminderDays`）ちょうどの日に1回だけ知らせる。その日にもう観察していれば送らない
  - 日数はプレートを作るときに選び、あとから編集でも変えられる。選ばなければ7日。「知らせない」も選べる（`null`）
  - 今あるプレートにも7が入る。仕込みから7日以上経ったものには、もう届かない
- **放っておいたプレート**: 最後に観察した日から（観察が無ければ仕込み日から）30日経ったプレートを知らせる。同じプレートを毎日知らせないよう、知らせたあとは次に観察するまで送らない。そのために、プレートに「最後に放置を知らせた日」を持つ
- リマインドと放置が同じ日に重なったら1通にまとめ、文面はリマインドにする。放置を知らせた記録は付ける

### 観察したかの判定

その日に次のどれかがあれば、そのプレートを観察した日とする。

- どれかのドロップに観察（`Observation.observedAt`）がある
- プレートのメモを書き換えた。そのために、プレートに「メモを最後に変えた日」（`notesUpdatedAt`）を持ち、`updatePlate` でメモの中身が変わったときだけ更新する。誤字を直しただけでも観察した扱いになるが、そこは割り切る

### バッジ

- 通知を受けたとき、Service Worker が `setAppBadge` で、その通知に入れたプレートの枚数を出す。アプリを開いたら消す（2026-10-19 に決め直した。理由は「結果」の4）
- ホーム画面に追加した iOS 16.4 以降と、Android の Chrome などで出る。出せない端末では何もしない

### 設定

- 設定画面に「通知」の欄を足す。この端末で通知を受けるかの切り替えと、テスト通知のボタン。あとで、2種類それぞれのオン・オフも足す
- 使っていない `notifNewPlate`・`notifStatus` は消し、`notifReminder` をリマインド全体のオン・オフに使う。放置の知らせのオン・オフの列を足す
- 端末ごとの受け口（Push の subscription）は、新しいテーブル `PushSubscription`（ユーザー・endpoint・鍵）に持つ。送って `404`・`410` が返ったものは消す。同じ端末で別のアカウントに入り直したら、受け口はそのアカウントに移す

## 作る順

1. Service Worker と、通知を受ける設定（許可・受け口の保存・テスト通知のボタン）。ここで、本人の iPhone に届くことを確かめる
2. 毎朝の Cron と、観察のリマインド（プレートの `reminderDays`、作成と編集の画面）
3. 放っておいたプレートの知らせ（`notesUpdatedAt`、放置を知らせた日）
4. バッジ

1 が終わった時点で、PWA としてオフラインのときの画面を出すかも考える（`docs/plans/2026-10-11-startup-speed.md`）。

## 確認

`npm run check` が通る。本番で、本人の iPhone（ホーム画面から開いたもの）にテスト通知が届くことを確かめる。Cron は、Vercel のダッシュボードから手で走らせて、届くことを確かめる。

## 結果

### 1: 通知を受ける設定（PR #47、2026-10-12）

- 本番で、本人の iPhone（ホーム画面から開いたもの）にテスト通知が届いた
- Chromium の受け口の endpoint は `fcm.googleapis.com` ではなく `jmt17.google.com` のような形だった。google.com の下をすべて許すと Apps Script など他人が使えるホストにも POST できてしまうので、`jmtNN.google.com` の形だけ許した
- headless の Chromium は、FCM からの配信を受け取れない。`sw.js` の確認は、DevTools の `ServiceWorker.deliverPushMessage` で push を直接渡して行った
- ローカルの `.env` の鍵は、本番とは別に作る（本番の秘密鍵は Vercel にだけある）

### 2: 毎朝の Cron と観察のリマインド

- プレートに `reminderDays`（既定 7、NULL なら送らない）を足し、作成・編集の画面で選べるようにした。今あるプレートにも 7 が入る
- 設定の `notifReminder` を、リマインド全体のオン・オフとして画面に出した。既定をオンにし、今の行もオンにした（これまで画面に無く、誰も選んでいなかったため）
- 朝9時に送るので「その日に観察したら送らない」はほとんど効かない。代わりに「リマインドの日以降に観察していれば送らない」にした
- Cron が抜けた日の分は、リマインドの日から3日のうちなら遅れて送る。3日で区切るのは、今あるプレートに昔の分がまとめて届かないように。送った分は `Plate.reminderSentFor` に記録し、二度は送らない。1通も届かなければ記録を戻し、翌朝にまた送る
- 観察したかは、ステップ2ではドロップの観察だけで見る。メモの更新はステップ3で足す
- マージ後、Vercel の本番に `CRON_SECRET` を入れて作り直した（2026-10-13）。ダッシュボードから Cron を手で走らせ、200 が返った。Vercel のプロジェクト名は `plate-manage-app`（リポジトリ名と違う）

### 3: 放っておいたプレートの知らせ

- 最後に観察した日（無ければ仕込み日）から30日目を「知らせる日」とし、リマインドと同じく、そこから3日のうちに1回だけ送る。送った分は `Plate.neglectSentFor` に記録する。次に観察すれば知らせる日が変わるので、また30日後に知らせる
- 3日で区切るのは、今あるプレートのうち、ずっと前から放ってあるものにまとめて届かないようにするため。そうしたプレートは、次に観察してから30日経つまで知らせない
- 1人に1通にまとめる。リマインドがあればリマインドの文面にし、放っておいたプレートも名前に並べる
- メモを書き換えた日を `Plate.notesUpdatedAt`（日本時間の日付）に持ち、リマインドと放置の両方で観察した日とみなす。中身が変わったときだけ付ける
- 設定に `notifNeglect` を足し、設定画面で切り替えられるようにした
- `notifNewPlate`・`notifStatus` はコードからは外したが、DB の列は残した。同じデプロイで列を消すと、ビルドがマイグレーションを当ててから新しい版に切り替わるまでの間、前の版が消えた列を読みに行って失敗するため。#49 が本番に出たあと、次の PR で列を消した

### 4: バッジ

- 「その日に観察どきのプレート」は、毎朝の通知に入れたプレートの枚数とした。アプリを開いたら、観察したかに関わらず消す（未読の数と同じ扱い）。開くたびにサーバーで数え直すと、起動のたびに問い合わせが1回増えるため
- 枚数は通知の中身（`PushPayload.badge`）で送り、`public/sw.js` が `setAppBadge` で出す。アプリを前に出して見ているときは出さない。テスト通知は枚数を持たないので、バッジを変えない
- 消すのは `components/app-badge-clearer.tsx`。ルートのレイアウトに置き、開いたときと、裏から前に戻ったとき（`visibilitychange`）に `clearAppBadge` を呼ぶ。ログイン画面で開いても消える
- headless の Chromium では、バッジが実際に出るかは見られない。`setAppBadge`・`clearAppBadge` を差し替えて、呼ばれ方を確かめた
