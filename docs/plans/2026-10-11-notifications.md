# 観察の時期と、放っておいたプレートを通知で知らせる（2026-10-11）

作成: 2026-10-11 / Issue #18

## 目的

本人から「通知をつけたい」「PWA のようなモバイルの機能をつけたい」という声が出た。知らせたいのは次の2つ（2026-10-11 に本人と決めた）。

- **観察のリマインド**: 仕込んでから決まった日数が経ったプレートを、観察するよう知らせる
- **放っておいたプレート**: しばらく観察していないプレートを知らせる

アプリを開いていなくても届くよう、Web Push で送る。

## 今あるもの

- `app/manifest.ts` で、ホーム画面に追加すると `standalone` で開ける。ヘルプ（`lib/help.ts`）に追加の手順もある
- Service Worker は無い
- `UserSettings` に `notifNewPlate`・`notifStatus`・`notifReminder` の列があり、`lib/actions/settings.ts` で書き換えられる。ただ、画面には出ていない。何にも使われていない

## 決めたこと（案）

### 届け方は Web Push

- `public/sw.js` に Service Worker を置き、`push` を受けたら通知を出し、押したらそのプレート（まとめた通知ならホーム）を開く
- 鍵は VAPID。公開鍵は `NEXT_PUBLIC_VAPID_PUBLIC_KEY`、秘密鍵は `VAPID_PRIVATE_KEY` として Vercel の環境変数に置く。送るのは `web-push` パッケージ
- iPhone では、ホーム画面に追加したアプリからしか通知を受けられない（iOS 16.4 以降）。設定画面で、ホーム画面から開いていないときは、その旨と手順（ヘルプ）を出す
- 通知の許可は、ボタンを押したときだけ求める。開いた途端には聞かない

### 送る時間と回数

- 1日1回、日本時間の朝9時に送る。Vercel Cron（`vercel.json` の `crons`、UTC の `0 0 * * *`）で `app/api/cron/notifications/route.ts` を呼ぶ。Hobby プランでも1日1回なら使える。`CRON_SECRET` で、Vercel 以外からは呼べないようにする
- 1人に1日1通にまとめる。知らせるプレートが1枚ならその名前を、複数なら「3枚のプレートが観察どきです」のように出す
- 知らせるものが無い日は送らない

### 何を知らせるか

ゴミ箱のプレートは除く。

- **観察のリマインド**: 仕込み日（`setupDate`）から、決まった日数（案: 1・3・7・14・28日）ちょうどのプレート。その日にもう観察していれば送らない
- **放っておいたプレート**: 最後の観察から（観察が無ければ仕込み日から）決まった日数（案: 14日）経ったプレート。同じプレートを毎日知らせないよう、知らせたあとは次に観察するまで送らない。そのために、プレートに「最後に放置を知らせた日」を持つ

### 設定

- 設定画面に「通知」の欄を足す。この端末で通知を受けるかの切り替えと、2種類それぞれのオン・オフ
- 使っていない `notifNewPlate`・`notifStatus` は消し、`notifReminder` を観察のリマインドに使う。放置の知らせの列を足す
- 端末ごとの受け口（Push の subscription）は、新しいテーブル `PushSubscription`（ユーザー・endpoint・鍵）に持つ。送って `404`・`410` が返ったものは消す

## 壁打ちで決めること

- リマインドの日数（1・3・7・14・28日でよいか、自分で変えられるようにするか）
- 放置とみなす日数（14日でよいか）
- 結晶を取り終えたプレートなど、もう見なくてよいプレートを除く方法。今は「終わった」という状態が無い。取り終えた目印（`HARVESTED`）があるプレートを除くか、プレートに「観察を終える」を足すか
- 送る時間（朝9時でよいか）

## 作る順

1. Service Worker と、通知を受ける設定（許可・受け口の保存・テスト通知のボタン）。ここで、本人の iPhone に届くことを確かめる
2. 毎朝の Cron と、観察のリマインド
3. 放っておいたプレートの知らせ

1 が終わった時点で、PWA としてオフラインのときの画面を出すかも考える（`docs/plans/2026-10-11-startup-speed.md`）。
