# ドロップの描き方と入力の改善 実装計画

作成: 2026-09-25 / ブランチ: `feature/drop-form-improvements`

## 目的

ドロップ単位の記録（`docs/plans/2026-09-24-plate-drops.md`）を本番に出したあと、本人が使ってみて3つの要望が出た。

1. **ハンギング3ドロップの並び**: 今は大きい丸の中に3つが横一列に並んでいる。実物に合わせ、上に1つ・下に2つの三角形に並べたい。丸の上には、向き（1番の位置）を示す短い縦線を描く
2. **作成時にも同じ描き方で見せる**: 作成画面と「まとめて追加」のウェル選択は、ただの丸の格子になっている。詳細画面と同じ描き方（SITTING の4つの丸と溝、HANGING の大きい丸と3つのドロップ）で見せたい
3. **置き場所ごとの濃度**: 今は置き場所の番号（何個使うか）を選べるだけで、濃度は全部のドロップで1つになる。置き場所ごとに濃度を決めたい

## 決まっていること

- サンプル名は、まとめて入れるドロップすべてで共通の1つのまま。濃度だけを置き場所ごとに入れる
- 置き場所の番号の意味は変えない。ハンギングの1番は上、2番は左下、3番は右下になる。本番のドロップは番号で持っているので、並びを変えても移し替えは要らない
- DB のスキーマは変えない。1つのドロップが持つ濃度は、今も `Drop.concentration` の1つだけ

やらないこと: 置き場所ごとのサンプル名、1ドロップの種別の見た目の変更。

## 設計

### 描き方は `well-shape.tsx` に足す

置き場所の位置は `components/well-shape.tsx` の `SHAPES` に % で持っている。`HANGING-3` の座標を三角形に置き換え、向きの縦線を `orientationMark` として足す。グリッド・シート・作成画面のどれもこの部品を通るので、1か所直せば全部に効く。

### 作成時のウェル選択を `WellShape` で描く

`components/well-grid-selector.tsx` に、描き方（`layout`・`maxDrops`）と選んだ置き場所を渡す。選んだウェルでは、選んだ置き場所を塗る。置き場所がまだ1つも選ばれていないときは、選んだウェルに枠を付けて見分ける。置き場所の選択も、番号のボタンをやめ、ウェルのシートと同じ大きい図を押す形にする（`WellShape` の `onSlotClick`）。

### まとめて入れる内容の形を変える

`bulk-drop-form.tsx` の `DropBatch` と、サーバーの `dropBatchSchema` を次の形にする。

```ts
{
  positions: string[];              // "A1" 形式
  sampleName: string;
  drops: { slot: number; concentration: string }[];  // 置き場所ごとの濃度
}
```

`slots` と `concentration` の2つの欄を `drops` 1つにまとめる。同じ置き場所が2回来たら、どちらの濃度を採るか決められないので拒否する（zod の `refine`）。`createPlate` と `bulkCreateDrops` は `drops` を読んでドロップを作る。フォームには、選んだ置き場所ごとに濃度の欄を1つずつ出す。1ドロップの種別では置き場所の番号を出さず、今と同じ「濃度」欄1つにする。

## 実測との差分

（実装しながら、計画と違ったことをここに書き足す）

- Phase 1（2026-09-25）
  - ハンギング3ドロップの座標は、本人が描いた図から割合を取った（大きい丸に対して、1番は中心の少し上、2番・3番は下の左右）。向きの縦線は、丸の上端をまたいで少し内側まで描く
  - `WellShape` の置き場所ボタンの `aria-pressed` は、`selectedSlot` を渡さない使い方（作成画面で複数を選ぶ）では「塗られているか」を表す。シートのように1つを選ぶ使い方では、今までどおり選んだ置き場所だけが押された状態になる
  - 作成画面で、置き場所を1つも選んでいないときは塗る所が無いので、選んだウェルに枠を付けて見分ける
- Phase 2（2026-09-25）
  - フォームの状態も、サーバーへ送る形に合わせて `drops: { slot, concentration }[]` にした。置き場所を外すとその濃度も消え、付け直すと空欄から始まる
  - 同じ置き場所の重複は、スキーマで拒否するようにした。そのため Action 側で置き場所を `Set` にまとめる処理は消した（ウェルの位置の重複は、今までどおり Action でまとめる）
  - 作成画面で種別を変えると、置き場所と一緒に濃度も戻る。今までは濃度を残していたが、置き場所ごとの値になったので、形の違う種別へは持ち越さない。サンプル名は今までどおり残す
  - 濃度の欄の見出しは「濃度 · 置き場所 1」の形にした。1ドロップの種別では「濃度」だけ
  - レビューで、選んでいる種別のカードを押し直すと入力が全部消えることが分かった。同じ種別なら何もしないようにした。フォームの純関数（`toDropBatchInput`・`isDropBatchComplete`）のテストも足した
- 本番（2026-09-25）
  - Phase 1・2 は PR #4（`c2f8ff9`）で出した。PR #4 がマージされたあとに Phase 3 のコミットを同じブランチへ push してしまい、PR #5（`c5f0cb9`）として出し直した
  - どちらも本番デプロイは成功した。スキーマの変更は無いので、DB 側で確かめることは無かった
  - 画面は本人が本番で確かめた。ハンギングの三角形の並び、列番号の位置、置き場所の図の大きさ、置き場所ごとの濃度、クリアの動きのどれも問題なかった
  - 1回の入力で入れられるサンプル名が1つなのが気になった。ただ、作成したあとに「まとめて追加」を繰り返せばウェルごとに違うサンプルを入れられるので、今回は変えないことにした
