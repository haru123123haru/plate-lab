# 手元のプレートを CSV でまとめて登録する（2026-10-06）

作成: 2026-10-06

## 目的

アプリを使う前から手元にあるプレートは、今は作成画面から1枚ずつ入れるしかない。1枚に入れられるサンプルは1種類なので、違うサンプルが混ざったプレートは、作ったあとにウェルのシートから1ドロップずつ足すことになる。数が多いと現実的でない。

Excel などで決まった形の表を作り、CSV で取り込めば、プレートとドロップ、必要なら観察もまとめて登録されるようにする。

手元のデータに決まった形は無い（2026-10-06 に確認）。そのため、取り込む形はこちらで決め、テンプレートを配る。

## 決めたこと

### 1行に1ドロップの、縦に長い表にする

ウェルマップの形（行×列）の表にすると、プレート1枚ごとに表を分けることになり、置き場所や濃度も入れにくい。1行に1ドロップを書き、プレートの欄は同じプレートの行に繰り返して書く。Excel のフィルタや並べ替えがそのまま使える。観察を書くときは、1行に1つの観察を書く（→「観察は任意で足せる」）。

| 列 | 中身 | 必須 | 例 |
| --- | --- | --- | --- |
| `plate_name` | プレート名。同じファイルで同じ名前の行は、1枚のプレートにまとめる | 必須 | `Lys-2026-08-01` |
| `plate_type` | プレートタイプの名前。共有か自分のタイプと、名前が完全に一致するもの | 必須 | `24 Well - Sitting 4 Drop` |
| `setup_date` | 仕込み日。`2026-08-01` か `2026/8/1` | 空なら取り込んだ日（日本時間） | `2026/8/1` |
| `reservoir` | リザーバー条件のテンプレート名 | 任意 | `MPD` |
| `screening` | スクリーニング条件のテンプレート名 | 任意 | `PEG` |
| `plate_notes` | プレートのメモ | 任意 | |
| `well` | ウェルの位置 | 空ならドロップの無いプレートとして作る | `A1` |
| `slot` | 置き場所 | 空なら 1 | `2` |
| `sample` | サンプル名 | `well` があれば必須 | `lysozyme` |
| `concentration` | 濃度 | `well` があれば必須 | `10 mg/mL` |
| `drop_notes` | ドロップのメモ | 任意 | |
| `observed_on` | 観察日。書き方は `setup_date` と同じ | 観察を書くなら必須 | `2026/8/15` |
| `mark` | 目印。`POSSIBLE`・`CRYSTAL`・`HARVESTED` か、`怪しい`・`結晶あり`・`結晶取り済み` | 任意 | `結晶あり` |
| `observation_notes` | 観察のメモ | 任意 | `針状の結晶` |

- 見出しの行は、英語（上の名前）と日本語（`プレート名`・`プレートタイプ`・`仕込み日`・`リザーバー`・`スクリーニング`・`プレートのメモ`・`ウェル`・`置き場所`・`サンプル名`・`濃度`・`ドロップのメモ`・`観察日`・`目印`・`観察のメモ`）のどちらでも受ける。列の順番は問わない。知らない列は無視する
- プレートの欄（`plate_type`〜`plate_notes`）は、同じプレートの行で値が違えばエラーにする。空の行は、ほかの行の値を使う（2行目以降を空にしてよい）
- テンプレートの名前が、共有と自分のもので重なって1つに決まらないときは、エラーにする

### 観察は任意で足せる

観察の列（`observed_on`・`mark`・`observation_notes`）は、無くても空でもよい（2026-10-06 に決定）。観察を書くときは、1行に1つの観察を書く。

- 同じファイルで同じプレートの同じウェル・置き場所の行は、同じドロップとして扱う。観察が何回かあれば、そのドロップの行を観察の数だけ並べる
- 同じドロップの2行目以降は、`sample`・`concentration`・`drop_notes` を空にしてよい。値を書くなら1行目と同じでなければエラーにする（どちらを採るか決められないため）
- `mark` か `observation_notes` があれば、`observed_on` は必須。`observed_on` だけで目印もメモも無い行はエラーにする（詳細画面の観察の追加と同じ決まり。`addObservationSchema`）
- 観察の行は、`well` が無ければエラーにする

```
plate_name,plate_type,well,slot,sample,concentration,observed_on,mark,observation_notes
Lys-0801,24 Well - Sitting 4 Drop,A1,1,lysozyme,10 mg/mL,2026/8/8,,小さな沈殿
Lys-0801,,A1,1,,,2026/8/15,結晶あり,針状の結晶
Lys-0801,,A1,2,thaumatin,5 mg/mL,,,
```

### 既にあるものと重なっても止めない

同じ名前のプレートが既にあっても、新しく作る（2026-10-06 に決定）。一覧で絞り込めば、重なりに気づける。サンプル名の揺れ（`lysozyme` と `Lysozyme`）もそのまま入る。重なったサンプルを見つける機能は、あとで別に考える（バックログに足す）。

同じファイルの中で同じプレートの同じウェル・置き場所が2回出たときは、同じドロップの観察として扱う（→「観察は任意で足せる」）。

### 全部確かめてから、全部入れる

1. ファイルを選ぶと、ブラウザで読み、すべての行を確かめる
2. 取り込まれる内容（プレートごとの名前・タイプ・ドロップ数）と、問題のある行（行番号と理由）を表で見せる
3. 問題が1つも無いときだけ「取り込む」を押せる。押すと、全部のプレートを1つのトランザクションで作る。途中で失敗したら何も入らない

一部の行だけ入ると、どこまで入ったかを利用者が確かめる手間が増える。直して出し直すほうが分かりやすい。

### 文字コードは UTF-8 と Shift_JIS を読む

日本語の Excel で「CSV」として保存すると Shift_JIS になる。「CSV UTF-8」なら UTF-8（BOM つき）。BOM があれば UTF-8 として読み、無ければ UTF-8 として厳密に読んでみて、だめなら `TextDecoder("shift_jis")` で読む。`.xlsx` はそのままでは読まない（ライブラリが要るので、要望が出たら考える）。

### 上限

1回で 50 枚・2000 行まで（2026-10-06 に決定）。Server Action に送る量（既定で 1MB）と、1つのトランザクションの時間に収めるため。トランザクションの時間の上限は 30 秒にする（既定の 5 秒では、96 Well を数十枚作ると足りない）。

### 置き場所

設定の「データ」に「CSV から取り込む」（`/settings/import`）を足す。テンプレート（見出しと例の行が入った CSV、UTF-8 の BOM つき）はこの画面からダウンロードする。ヘルプページにも節を足す。

## 作り

- **`lib/csv.ts`**: CSV を行の配列にする純粋関数。ダブルクォートで囲んだ値（カンマ・改行・`""` を含む）と、CRLF・LF を扱う。依存は足さない
- **`lib/plate-import.ts`**: 行の配列と、使えるプレートタイプ・テンプレートの一覧を受け取り、プレートごとにまとめた内容とエラーの一覧を返す純粋関数。ブラウザの確認画面で使う。サーバーは名前ではなく ID を受けるので、これは使わず、Zod（`importPlatesSchema`）とタイプの形で確かめ直す
- **`lib/actions/plate-import.ts`**: `importPlates()`。ブラウザから来たまとめた内容を Zod で確かめ直し、プレートタイプとテンプレートを `accessiblePlateTypeWhere` などで引き直してから、1つのトランザクションで作る。ブラウザの確認は表示のためで、信用しない
- **`app/(app)/settings/import/`**: 画面。`page.tsx` で使えるプレートタイプとテンプレートを取り、`import-client.tsx` に渡す

## やらないこと

- サンプルの見た目（アイコンと色）の取り込み
- 既にあるプレートへの追記や上書き
- `.xlsx` の読み込み、書き出し（エクスポート）

## 確認

`npm run check` が通る。ブラウザ（Playwright、402px）で次を確かめる。

- テンプレートをダウンロードし、そのまま取り込むと例のプレートができる
- Excel で「CSV」（Shift_JIS）と「CSV UTF-8」で保存したファイルの両方が読める
- 1枚に違うサンプルが混ざったプレートと、4 Drop のプレートの置き場所が正しく入る
- 観察を書いた行は詳細画面のウェルのシートに出て、目印はウェルマップに輪で出る。観察の列が無いファイルも取り込める
- 問題のある行があると、行番号と理由が出て、取り込めない
